Training コードレビュー用メモ
==============================

目的
----
このディレクトリは、Slay the Spire 2 の教師データを学習用に整形し、通常 Policy、
Value、Choice Policy を学習・評価するための Python コード群です。

大きな流れ
----------
1. Combat 側などで生成された trajectory / decision JSONL を受け取る。
2. export_training_dataset.py が Data Contract v1 に沿った学習用 export を作る。
   - complete_train.jsonl / complete_validation.jsonl / complete_test.jsonl
   - partial_* 系
   - export_metadata.json
   - id dictionary 群
3. sts2_training/encoding.py が state / action / card / potion などをテンソル化する。
4. sts2_training/dataset.py が通常 Policy 用 Dataset / collate を提供する。
5. sts2_training/value_targets.py が Value 用ターゲットを派生生成する。
6. sts2_training/model.py が 3 系統のモデルを定義する。
   - CandidatePolicyNet: 通常 action 選択用 Policy
   - ValueNet: state から win / final HP / remaining decisions を推定
   - ChoicePolicyNet: choice_card 候補カードのランキング用
7. train_*.py が各モデルを学習し、checkpoints/ と reports/ に成果物を出す。
8. sts2_training/inference.py / choice_inference.py と run_*_demo.py が推論動作確認を行う。
9. validate_*.py / audit_*.py / analyze_*.py がデータ品質・評価・追加分析を行う。

推奨読む順番
------------
1. DATA_CONTRACT.md
   - 入出力 JSONL の前提、フィールド、分割、辞書の約束を先に押さえる。

2. export_training_dataset.py
   - 元データから学習 export を作る入口。
   - ここで dataset_kind、split、metadata、dictionary、decision row の形が決まる。

3. sts2_training/encoding.py
   - モデルへ渡すテンソル表現の中心。
   - state_dim、各 vocab、action numeric features の意味を確認する。

4. sts2_training/dataset.py
   - 通常 Policy 用のデータ読み込み。
   - teacher index の照合、choice_card の除外、collate_decisions の padding / mask を確認する。

5. sts2_training/model.py
   - モデル構造の全体像。
   - CandidatePolicyNet、ValueNet、ChoicePolicyNet の入力・出力 shape をここで把握する。

6. train_imitation.py
   - 通常 Policy の学習ループ。
   - run_epoch、evaluate_detailed、checkpoint 保存、metrics 出力の基本形を見る。

7. sts2_training/value_targets.py
   - Value 学習用の派生ラベル生成。
   - final HP、win、remaining decisions のターゲット化を確認する。

8. train_value.py
   - ValueNet の学習。
   - train_imitation.py と似た構成なので、差分として Value 固有の loss / metrics を読む。

9. sts2_training/choice_data.py
   - Choice Policy 専用データの入口。
   - choice teacher data の scope filter、split、choice meaning dictionary、merge map を確認する。

10. train_choice_policy.py
    - ChoicePolicyNet の初期学習と比較評価。
    - 通常 Policy checkpoint から state_net / card_embedding をコピーし、freeze / no-meaning / finetune を比較する流れを見る。

11. analyze_choice_meaning.py
    - choice meaning が効いているかの追加分析。
    - per-token 分析、冗長性チェック、merge proposal、merged-token ablation を確認する。

12. train_choice_policy_8token.py
    - 13-token choice meaning を 8-token merge 後に学習する最終寄りの実験。
    - 3 seed 集計、baseline 比較、best checkpoint 保存、provenance 出力を見る。

13. sts2_training/inference.py と sts2_training/choice_inference.py
    - 学習済み checkpoint を実運用風に呼ぶラッパ。
    - fallback 条件、mask、返却 payload の形を確認する。

14. run_inference_demo.py と run_choice_inference_demo.py
    - 推論ラッパの実行例。
    - レビュー時は「どの checkpoint をどう読んで、どんな結果を出すか」の確認用。

15. validate_export.py / validate_training_pipeline.py / audit_choice_teacher_data.py
    - 最後に検証・監査スクリプトを読む。
    - 主要ロジックを読んだ後の方が、何を守ろうとしているチェックか分かりやすい。

主要ファイル別の役割
--------------------
export_training_dataset.py
  学習用データ export の生成担当。元 run の形式差を吸収し、split manifest、metadata、
  dictionaries、JSONL を出力する。

sts2_training/encoding.py
  JSON の observation / legal action を PyTorch tensor に変換する担当。
  学習・推論の両方が同じ encoder を使うため、互換性上の重要度が高い。

sts2_training/dataset.py
  通常 Policy 用 Dataset。choice_card は通常 Policy から除外し、別系統の Choice Policy に渡す設計。

sts2_training/model.py
  ネットワーク定義。mask 自体は masked_logits でまとめられている。

train_imitation.py
  CandidatePolicyNet の教師あり学習。通常 action 選択のベースライン。

sts2_training/value_targets.py / train_value.py
  ValueNet 用の教師ラベル生成と学習。

sts2_training/choice_data.py
  choice_card 専用 Dataset と split / dictionary / merge map の定義。

train_choice_policy.py
  choice_card 候補ランキングの初期学習・評価。ChoicePolicyNet は通常 Policy checkpoint の共有可能部分を流用する。

analyze_choice_meaning.py
  choice meaning token の有効性分析。レポート生成寄りで、実験ロジックが多い。

train_choice_policy_8token.py
  merge map 適用後の Choice Policy 学習。複数 seed 集計と最終 checkpoint 保存を行う。

sts2_training/inference.py / sts2_training/choice_inference.py
  学習済みモデルを呼び出す推論 API 風ラッパ。

読むときの注意点
----------------
- 通常 Policy と Choice Policy は別系統。
  通常 Policy 側では choice_card を除外し、Choice Policy 側で choice_card 候補だけをランキングする。

- complete / partial の区別がある。
  初期学習コードは基本的に usable_complete を主対象にしている。

- split は trajectory 単位。
  decision 単位でランダム分割していないため、同一 trajectory のリークを避ける設計。

- Choice Policy は teacher_action が choice_card の行だけを in-scope とする。
  choice_confirm / choice_skip などはこの pass ではランキング対象外。

- ChoicePolicyNet は通常 Policy checkpoint の state_net と card_embedding をコピーできる。
  ただし action head は Choice 専用で、通常 Policy の入出力は変更しない。

- reports/ と checkpoints/ は成果物。
  コードレビューでは、まず *.py と DATA_CONTRACT.md を読み、必要に応じて reports の JSON / MD で実験結果を確認するのが効率的。

レビュー時の近道
----------------
1. データ仕様の妥当性を見るなら:
   DATA_CONTRACT.md -> export_training_dataset.py -> validate_export.py

2. 通常 Policy の学習を追うなら:
   encoding.py -> dataset.py -> model.py -> train_imitation.py -> inference.py

3. Value 学習を追うなら:
   encoding.py -> value_targets.py -> model.py -> train_value.py

4. Choice Policy を追うなら:
   choice_data.py -> model.py の ChoicePolicyNet -> train_choice_policy.py -> train_choice_policy_8token.py -> choice_inference.py

5. 実験結果の解釈を見るなら:
   train_choice_policy.py -> analyze_choice_meaning.py -> reports/choice_meaning_analysis_report.md
